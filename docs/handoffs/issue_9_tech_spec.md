# Technical Specification: Issue #9 - Implement Global Exception Handling Middleware

## Overview

Implement a global exception handling mechanism using ASP.NET Core's built-in `IExceptionHandler` interface to intercept all unhandled exceptions before they surface to the client. The handler wraps errors in the project's existing `ApiResponse` format, logs structured diagnostics server-side, and never leaks internal details to API consumers.

No new domain entities, database changes, or migrations are introduced in this issue.

---

## Architecture & Design Decisions

### Approach: `IExceptionHandler` (not custom `IMiddleware`)

| Option | Pros | Cons |
|---|---|---|
| **`IExceptionHandler` (chosen)** | Built-in ASP.NET Core 8+ contract; integrates with `UseExceptionHandler()`; supports chaining multiple handlers; framework handles edge cases (response already started, etc.). | Requires `AddProblemDetails()` registration as a framework dependency. |
| Custom `IMiddleware` | Full pipeline control; no framework dependencies beyond DI. | Must manually handle edge cases (response already started, body already written); duplicates what the framework already does well. |

**Decision:** Use `IExceptionHandler` because the project targets .NET 10, and this is the framework-recommended approach. It produces less boilerplate and is inherently safer against partial-response edge cases.

### Environment-Aware Error Messages

- **Development:** Include exception type and message (e.g., `"NullReferenceException: Object reference not set..."`) to aid local debugging.
- **Non-Development (Staging/Production):** Return a generic message (`"An unexpected error occurred. Please try again later."`) — never expose stack traces, class names, or connection strings.

Stack traces are **never** included in the response body in any environment.

### Logging Strategy

- Log at `Error` level with the full exception object (type, message, stack trace) plus the request method and path.
- Use parameterized structured logging templates per `@rule_testing_observability` — no string interpolation.

## API Contract

### Error Response Shape

All unhandled exceptions return **HTTP 500** with `Content-Type: application/json` and the following body using the existing `ApiResponse` type:

**Non-Development (Production/Staging):**

```json
{
  "success": false,
  "message": "An unexpected error occurred. Please try again later.",
  "errors": []
}
```

**Development:**

```json
{
  "success": false,
  "message": "NullReferenceException: Object reference not set to an instance of an object.",
  "errors": []
}
```

## Application Layer Boundaries

### New Class: `GlobalExceptionHandler`

**File:** `KanbAI-Core/KanbAI-Core/Middleware/GlobalExceptionHandler.cs`
**Namespace:** `KanbAI_Core.Middleware`

```csharp
namespace KanbAI_Core.Middleware;

public sealed class GlobalExceptionHandler : IExceptionHandler
{
    private readonly ILogger<GlobalExceptionHandler> _logger;
    private readonly IHostEnvironment _environment;

    public GlobalExceptionHandler(
        ILogger<GlobalExceptionHandler> logger,
        IHostEnvironment environment) { ... }

    public async ValueTask<bool> TryHandleAsync(
        HttpContext httpContext,
        Exception exception,
        CancellationToken cancellationToken) { ... }
}
```

**Contract:**

- Constructor receives `ILogger<GlobalExceptionHandler>` and `IHostEnvironment` via DI (constructor injection per `@rule_code_standards`).
- `TryHandleAsync` always returns `true` (handles all unhandled exceptions; no exception falls through to the framework default).
- Sets `httpContext.Response.StatusCode` to `500`.
- Serializes `ApiResponse.Fail(message)` to the response body via `httpContext.Response.WriteAsJsonAsync(...)`.

### Pipeline Registration (`Program.cs`)

**Service registration (before `builder.Build()`):**

```csharp
builder.Services.AddExceptionHandler<GlobalExceptionHandler>();
builder.Services.AddProblemDetails();
```

**Middleware registration (after `builder.Build()`, before `UseHttpsRedirection` and endpoints):**

```csharp
app.UseExceptionHandler();
```

> `AddProblemDetails()` is required as a framework dependency for `UseExceptionHandler()` even though we return `ApiResponse` — it acts as a fallback safety net if any future `IExceptionHandler` returns `false`.

### `Program` Class Accessibility

To enable integration testing with `WebApplicationFactory<Program>`, add the following marker at the end of `Program.cs`:

```csharp
public partial class Program { }
```

This allows the test project to reference the implicit `Program` class generated by top-level statements.

## Implementation Steps for @agent_developer

Follow these steps in order, referencing `@rule_code_standards` and `@rule_testing_observability`:

### Step 1 — Create the `GlobalExceptionHandler` class

1. Create the directory `KanbAI-Core/KanbAI-Core/Middleware/` if it does not exist.
2. Create `GlobalExceptionHandler.cs` implementing `Microsoft.AspNetCore.Diagnostics.IExceptionHandler`.
3. Use file-scoped namespace `KanbAI_Core.Middleware`.
4. Mark the class as `sealed` (no reason to inherit from it).
5. Inject `ILogger<GlobalExceptionHandler>` and `IHostEnvironment` via constructor.
6. In `TryHandleAsync`:
   - Log the exception at `Error` level using parameterized structured logging: `"Unhandled exception occurred while processing {RequestMethod} {RequestPath}"` with the full exception object passed as the first argument to `LogError`.
   - Build the error message: if `_environment.IsDevelopment()`, use `$"{exception.GetType().Name}: {exception.Message}"`; otherwise use the string `"An unexpected error occurred. Please try again later."`.
   - Set `httpContext.Response.StatusCode = StatusCodes.Status500InternalServerError`.
   - Write `ApiResponse.Fail(message)` to the response body using `httpContext.Response.WriteAsJsonAsync(response, cancellationToken)`.
   - Return `true`.

### Step 2 — Register services and middleware in `Program.cs`

1. **Before `builder.Build()`:** Add `builder.Services.AddExceptionHandler<GlobalExceptionHandler>();` and `builder.Services.AddProblemDetails();` after the existing service registrations.
2. **After `builder.Build()` but before `app.UseHttpsRedirection()` and endpoint mappings:** Add `app.UseExceptionHandler();`.
3. The final middleware order should be:
   ```
   app.UseExceptionHandler();    // ← NEW: must be first
   app.UseHttpsRedirection();
   // ... endpoints
   ```
4. Add `public partial class Program { }` at the very end of `Program.cs` (after the `WeatherForecast` record) to expose the class for integration testing.

### Step 3 — Verify build and existing tests

1. Run `dotnet build` on the solution to confirm zero errors and zero new warnings.
2. Run `dotnet test` to confirm all 61 existing tests still pass without modification.

## Edge Cases for @agent_tester_qa

The QA agent should create **integration tests** using `WebApplicationFactory<Program>` (already referenced in the test project's `.csproj` via `Microsoft.AspNetCore.Mvc.Testing`) to verify the middleware behaves correctly end-to-end.

### Test Class: `GlobalExceptionHandlerTests`

**File:** `KanbAI-Core/KanbAI-Core.Tests/Middleware/GlobalExceptionHandlerTests.cs`

**Test infrastructure:**

- Use `WebApplicationFactory<Program>` as the base.
- Register a test-only endpoint that always throws (e.g., `app.MapGet("/test/throw", () => { throw new InvalidOperationException("Test exception message"); })`) via `WithWebHostBuilder` → `ConfigureServices` or by overriding `CreateHost`.
- To test non-Development behaviour: use `.WithWebHostBuilder(b => b.UseEnvironment("Production"))`.
- The factory must disable or bypass the `Authorize` fallback policy for test requests (the existing `Program.cs` sets `FallbackPolicy = DefaultPolicy` with Negotiate auth, which will reject unauthenticated test requests). Override in the test factory by calling `builder.ConfigureServices(s => s.AddAuthorization(o => o.FallbackPolicy = null))` or use `AllowAnonymous` on the test endpoint.

**Required test scenarios:**

| # | Test Name | Assertion |
|---|---|---|
| 1 | `UnhandledException_Returns500StatusCode` | Hit `/test/throw`; verify response status code is `500`. |
| 2 | `UnhandledException_ReturnsJsonContentType` | Verify `Content-Type` header is `application/json`. |
| 3 | `UnhandledException_ReturnsApiResponseFormat` | Deserialize body as `ApiResponse`; verify `Success == false` and `Message` is not null or empty. |
| 4 | `UnhandledException_InNonDevelopment_DoesNotLeakExceptionDetails` | Set environment to `"Production"`; verify the response message does **not** contain `"InvalidOperationException"` or `"Test exception message"`. |
| 5 | `UnhandledException_InDevelopment_IncludesExceptionTypeAndMessage` | Set environment to `"Development"`; verify the response message contains `"InvalidOperationException"` and `"Test exception message"`. |
| 6 | `UnhandledException_ResponseBody_NeverContainsStackTrace` | In both Development and Production, verify the serialized body does **not** contain `"   at "` (stack trace line prefix). |
| 7 | `ExistingWeatherEndpoint_ContinuesToWork` | `GET /weatherforecast` returns `200` with a valid `ApiResponse` body (`Success == true`). |
