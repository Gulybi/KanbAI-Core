# Issue #6: Initialize .NET Web API and Project Structure - Technical Specification

## Overview
This document outlines the technical steps required to initialize the foundational .NET Web API project for KanbAI-Core and establish the core folder structure.

## Architecture & Project Structure
The solution will follow a clean, layered folder structure within a single Web API project initially, setting the stage for future separation if needed.

**Target Project Name:** `KanbAI.Api` (or `KanbAI.Core.Api`)
**Framework:** .NET 8.0 (or latest stable)

### Directory Structure
The following directories must be created at the root of the API project:
- `Controllers/`: For API endpoints (REST controllers).
- `Models/Entities/`: For Domain models and EF Core entities.
- `Data/`: For `DbContext` and database configurations.
- `Services/`: For business logic and application services.
- `DTOs/`: For Data Transfer Objects (Requests/Responses).

## Implementation Steps for @agent_developer
Please follow these steps strictly, referencing `@rule_code_standards`:

1. **Initialize the Web API Project:**
   - Navigate to the `KanbAI-Core` directory (or solution root).
   - Run the .NET CLI command to create a new Web API project: `dotnet new webapi -n KanbAI.Api`.
   - Add the new project to the existing solution (`KanbAI-Core.sln`) using `dotnet sln add KanbAI.Api/KanbAI.Api.csproj`.

2. **Add .NET `.gitignore`:**
   - Generate a standard .NET `.gitignore` file at the repository root using `dotnet new gitignore`.

3. **Create Core Directories:**
   - Inside the newly created `KanbAI.Api` project folder, create the following directories:
     - `Controllers`
     - `Models/Entities`
     - `Data`
     - `Services`
     - `DTOs`
   - Add a dummy `.gitkeep` file in each directory to ensure they are tracked by Git, or create them as part of the initial commit if they contain initial files.

4. **Clean Up Default Template (Optional but Recommended):**
   - Remove the default `WeatherForecastController.cs` and `WeatherForecast.cs` files generated by the template to maintain a clean starting point.

5. **Verify Build:**
   - Run `dotnet build` to ensure the project compiles successfully.
